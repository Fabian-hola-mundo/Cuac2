# POS: venta por voz — Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Dictar una venta en el POS (o desde un atajo en la pantalla de inicio) y que Groq la convierta en líneas del carrito, confirmadas por el usuario, registradas en el evento activo.

**Architecture:** Edge Function `pos-voz` (Groq Whisper + chat con JSON estricto + regla de evidencia en el servidor) → hoja de voz cargada con `import()` dinámico (`public/pos/voz.js`) → carrito y hoja de cobro existentes de `feat/pos-carrito` → `registrar_transaccion_pos`.

**Tech Stack:** Deno (Supabase Edge Functions), Groq OpenAI-compatible API, JS ESM sin build en `public/pos/`, Vitest vía `ng test`.

**Spec:** `docs/superpowers/specs/2026-10-09-pos-voz-design.md`

## Global Constraints

- Sin migraciones; se usa `registrar_transaccion_pos` tal cual.
- `pos-logic.js` y `sw.js` no cambian; caché en `pos-v4`.
- `index.html`, `pos-logic.js` y `sw.js` solo se tocan después del SHA final de POSFIX (`feat/pos-carrito`).
- `voz.js` y `voz-logic.js` se cargan solo con `import()` dinámico.
- Secretos: `GROQ_API_KEY` (obligatorio), `GROQ_MODEL` (por defecto `openai/gpt-oss-120b`). Transcripción `whisper-large-v3-turbo`, `language=es`.
- Audio ≤ 60 s y ≤ 10 MB; texto ≤ 500; observación ≤ 280; tiempo límite en el cliente de 20 s.
- Nunca se registra sin el toque del usuario.

## Review Focus

- «dos tote bags» sin decir cuáles → siempre duda, nunca adivinar (Task 1: prueba `evidencia: categoría ambigua`).
- Precio dictado no divisible (3 unidades por $100.000) → suma exacta (Task 2: prueba `repartirPrecio residuo`).
- Producto con combinaciones dicho sin combinación → duda de combinación (Task 1).
- La propuesta trae un id que ya no está en el catálogo local → se omite con aviso (Task 2).
- Tocar 🎙 sin internet o con el permiso del micrófono negado → mensaje claro, el POS sigue usable (Task 4, verificación manual).

### Task 1: Regla de evidencia (servidor)

- Test: `src/app/pos/evidencia.spec.ts`

**Interfaces:**
- Produces: `normalizar(s: string): string`; `palabrasDistintivas(producto, productosCategoria, categoria): string[]`; `validarPropuesta(modelo, catalogo, transcripcion): { lineas: LineaVoz[], dudas: DudaVoz[] }`, donde `catalogo = { productos: {id,nombre,categoria,precio,stock_actual}[], variantes: {id,producto_id,opciones,precio,stock_actual}[] }`, `modelo.lineas = {producto_id, variante_id|null, cantidad, fragmento}[]`, `modelo.dudas = {texto,cantidad,opciones:{producto_id,variante_id|null}[]}[]`, `LineaVoz = {producto_id, variante_id, cantidad}` y `DudaVoz = {texto, cantidad, opciones:{producto_id,variante_id}[]}`.

- [ ] Prueba: «dos tote bags por 80 mil» + línea del modelo `{Orquídeas, 2, fragmento:'dos tote bags'}` → 0 líneas, 1 duda con cantidad 2 y opciones = las 3 totes.
- [ ] Prueba: «una totebag orquídea en efectivo», fragmento `'totebag orquidea'` → 1 línea Orquídeas ×1.
- [ ] Prueba: un producto único en su categoría con fragmento `'la agenda'` (categoría `agenda`) → línea.
- [ ] Prueba: fragmento que no aparece en la transcripción → duda.
- [ ] Prueba: producto con variantes activas, `variante_id` null → duda con opciones = sus variantes; `variante_id` de otro producto → duda.
- [ ] Prueba: dudas del modelo con ids inexistentes → se filtran; si una duda queda sin opciones, se descarta. Cantidad no entera o < 1 → se descarta.
- [ ] Ejecutar `npx ng test --watch=false --include src/app/pos/evidencia.spec.ts` → FAIL.
- [ ] Implementar. Palabra distintiva: una palabra normalizada del nombre (≥ 3 letras) que no está en el nombre de la categoría ni en los nombres de los demás productos de la categoría. Coincide si la transcripción tiene esa palabra completa o comparte con ella un prefijo de ≥ 5 letras («orquidea» ~ «orquideas»). Con un solo producto en la categoría, basta con que el fragmento aparezca en la transcripción. Para variantes: algún valor de `opciones` normalizado aparece en la transcripción.
- [ ] Ejecutar → PASS. Commit `feat(pos-voz): regla de evidencia para no adivinar productos`.

### Task 2: Lógica de la propuesta en el cliente

**Files:**
- Create: `public/pos/voz-logic.js`, `public/pos/voz-logic.d.ts`
- Test: `src/app/pos/voz-logic.spec.ts`

**Interfaces:**
- Consumes: la forma de `Linea` de `public/pos/pos-logic.d.ts`.
- Produces: `repartirPrecio(lineas: Linea[], total: number): Linea[]`; `propuestaACarrito(propuesta, elecciones, productos, variantesPorProducto): { lineas: Linea[], omitidas: number }`, donde `elecciones = Record<dudaIndex, {producto_id, variante_id, cantidad}[]>`; `fusionarCarrito(carrito: Linea[], nuevas: Linea[]): Linea[]`; `dudasPendientes(propuesta, elecciones): number`; `observacionPrecio(dictado: number, catalogo: number): string`; `totalLineas(lineas): number`.

- [ ] Pruebas de `repartirPrecio`: [40000×2] a 70000 → Σ = 70000 con precio 35000; [A 40000×1, B 20000×1] a 30000 → 20000 / 10000; [A 10000×3] a 100000 → [A 33333×2, A 33334×1 con clave `…|v1`], Σ = 100000; precios 0 → reparto igual; total ≤ 0 → lanza error.
- [ ] Pruebas de `propuestaACarrito`: un id desconocido → `omitidas: 1`; la cantidad se limita a `stock_actual` (`stock_max`); `etiqueta_variante` igual a `etiquetaDe` (valores de `opciones` ordenados por clave, unidos con ` · `).
- [ ] Pruebas de `fusionarCarrito`: misma clave → suma con tope en `stock_max`; las claves `|v<n>` no se mezclan con la línea a precio de catálogo.
- [ ] Prueba: `observacionPrecio(70000, 80000)` → `'Precio dictado $70.000 (catálogo $80.000)'` (formato `es-CO`).
- [ ] Prueba: `dudasPendientes` cuenta las dudas cuya suma elegida ≠ `cantidad`.
- [ ] Ejecutar → FAIL; implementar; ejecutar → PASS. Commit `feat(pos-voz): lógica de propuesta, reparto de precio y fusión con el carrito`.
